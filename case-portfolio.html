INSIDE THE PROJECT

01 / The problem02 / The approach03 / The challenge04 / The outcome

The problem

The earlier site spread a short story across five near-identical pages, described me mainly as a web learner, and never mentioned the ML work I spend most of my time on. A legacy contact form also pointed to a PHP script that GitHub Pages cannot run.

The approach

The redesign puts About, Skills, Projects, Experience, and Contact on one page with sticky in-page navigation. Colors and spacing are defined as CSS custom properties, so light and dark themes share one set of components. Old page URLs redirect to the matching section.

The challenge

Add polish (theme switching, scroll reveals, a mobile menu) without hurting accessibility or hiding content. Everything is readable without JavaScript, motion respects reduced-motion settings, and every claim about a project states its scope.

The outcome

The home page now answers who I am, what I do, and how to reach me on the first screen. Every demo and repository is linked directly, and GitHub Pages publishes the site from the main branch.

Scope & next steps

There is no contact-message backend. The email link opens the visitor’s own email application, and the copy button puts the address on the clipboard.
